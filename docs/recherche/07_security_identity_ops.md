## 1. Identity: SAP Cloud Identity Services (IAS, IPS, Identity Directory, Authorization Management), SAP Cloud Identity Access Governance, SAP Identity Management end of maintenance and the Microsoft Entra ID path, SSO and principal propagation

### Takeaway
SAP Cloud Identity Services (Identity Authentication, Identity Provisioning, Identity Directory, Authorization Management) is SAP's strategic IAM layer for S/4HANA and BTP. SAP Identity Management 8.0 is end-of-maintenance: mainstream maintenance ends 31 Dec 2027 and extended maintenance runs to 2030 at extra cost. There is no SAP successor product. SAP and Microsoft recommend Microsoft Entra ID (with Entra ID Governance) for enterprise identity lifecycle, with Cloud Identity Services as the bridge into SAP applications.

### Cited Findings
**SAP Cloud Identity Services (umbrella)**
- SAP's product page names four capabilities: user provisioning, authentication and SSO, policy-based authorization management, and identity repositories. It positions the suite for cloud and hybrid identity management — [sap.com Cloud Identity Services](https://www.sap.com/products/financial-management/identity-management.html)
- SAP positions Cloud Identity Services as the core of its IAM strategy. It supports SAML, OIDC, X.509 and SCIM and is the single integration point for partner identity scenarios such as Entra — [SAP Community: Preparing for SAP IdM end of maintenance 2027](https://blogs.sap.com/t5/technology-blogs-by-sap/preparing-for-sap-identity-management-s-end-of-maintenance-in-2027/ba-p/13596101)
- **Licensing:** IAS and IPS come with SAP BTP by default. No extra licence is needed when they are used with an SAP cloud solution, an SAP on-premise application or an SAP system on SAP HANA Enterprise Cloud. Customers normally get one productive and one test tenant, and further tenants cost extra. Under CPEA, pricing is consumption-based — [consiness, Feb 2024](https://www.consiness.de/2024/02/21/das-ende-einer-aera-teil-2-4-sap-loesungen/?lang=en)
- A licensing advisory site claims IAS/IPS are bundled in RISE with free tiers (1,000 IAS authentication events per month, 500 IPS identities) and metering above that, and that Authorization Management is bundled in BTP entitlements. This is unverified vendor-marketing material and contains internally inconsistent price figures — [saplicensingexperts.com](https://saplicensingexperts.com/blog/sap-identity-access-management-licensing)

**Identity Authentication (IAS)**
- Provides SSO and acts as the central identity provider for cloud and on-premise applications with standard authentication methods. Often called "middleware" rather than a full IAM suite, positioned next to Microsoft Entra — [consiness](https://www.consiness.de/2024/02/21/das-ende-einer-aera-teil-2-4-sap-loesungen/?lang=en)
- In the Entra target architecture, Entra ID is the IdP (SAML, OIDC, Kerberos). For SAP cloud and BTP apps, Entra federates with SAP Cloud Identity Services — [Microsoft Learn: Migrate from SAP IDM](https://learn.microsoft.com/en-us/entra/id-governance/scenarios/migrate-from-sap-idm)

**Identity Provisioning (IPS) and Identity Directory**
- Entra provisions users and groups into SAP Cloud Identity Services (Identity Directory). Cloud Identity Services then provisions them into SAP S/4HANA Cloud, SAP S/4HANA on-premise (through SAP Cloud Connector), AS ABAP and others. Groups can become roles in the target apps. The schema mappings have to be confirmed first — [Microsoft Learn](https://learn.microsoft.com/en-us/entra/id-governance/scenarios/migrate-from-sap-idm)
- Identity Directory is the store where Authorization Management policies and roles are assigned to users, through the admin console or the SCIM API — [SAP Learning: Authorization Management Service](https://learning.sap.com/courses/exploring-the-fundamentals-of-sap-system-security/describing-the-authorization-management-service)

**Authorization Management (AMS)**
- Central, policy-based authorization (RBAC, least privilege) across SAP and non-SAP applications. Developers define access policies (action plus resource, usually a business object) inside the application. Policies are evaluated at runtime. Admins set restriction values and assign SAP-delivered or customer-derived policies. Integration focuses on CAP on BTP — [SAP Learning](https://learning.sap.com/courses/exploring-the-fundamentals-of-sap-system-security/describing-the-authorization-management-service)

**SAP Cloud Identity Access Governance (IAG)**
- A cloud access-governance service on BTP: access analysis (SoD), business role management, access reviews and access-request workflows. One author called it the "cloud successor to GRC" in early development, possibly competing with SAP GRC for SAP HANA — [consiness](https://www.consiness.de/2024/02/21/das-ende-einer-aera-teil-2-4-sap-loesungen/?lang=en)
- IAG covers access risk and governance analysis. It was never positioned to replace IdM's provisioning (fulfilment) role — [Pathlock](https://pathlock.com/blog/sap-idm-end-of-life/)
- IAG remains available and its roadmap adds functions, as the cloud counterpart to on-premise Access Control — [IBsolution](https://www.ibsolution.com/academy/blog_en/cyber-security/sap-identity-and-access-management/maintenance-for-sap-access-control-expires-in-2027-what-comes-next)
- An SAP GRC development deck (Aug 2025) lists IAG as an extended capability that needs an additional licence. Planned: integration with more cloud applications — [ASUG/SAP GRC update deck, Aug 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250821_sap_security_governance_risk_and_compliance_update.pdf)
- **Entra integration (Preview, per Microsoft Learn last updated 17 Oct 2025):** Entra entitlement management can add SAP IAG business roles to access-package catalogs. Approved access drives role assignment in IAG and downstream SAP apps. Microsoft says future capabilities will add integration with SAP Access Control — [Microsoft Learn](https://learn.microsoft.com/en-us/entra/id-governance/scenarios/migrate-from-sap-idm)

**SAP Identity Management (IdM) 8.0 — END OF MAINTENANCE**
- Sunset announced Feb 2024. Mainstream maintenance ends 31 Dec 2027. Extended maintenance runs to 2030 at added cost. SAP has confirmed there is no successor product — [Pathlock](https://pathlock.com/blog/sap-idm-end-of-life/); [SAP Community blog](https://blogs.sap.com/t5/technology-blogs-by-sap/preparing-for-sap-identity-management-s-end-of-maintenance-in-2027/ba-p/13596101)
- The recommended path is Microsoft Entra ID for enterprise identity lifecycle, with SAP Cloud Identity Services for SAP-specific integration. SAP and Microsoft developed the migration guidance together — [SAP Community blog](https://blogs.sap.com/t5/technology-blogs-by-sap/preparing-for-sap-identity-management-s-end-of-maintenance-in-2027/ba-p/13596101); [Pathlock](https://pathlock.com/blog/sap-idm-end-of-life/)
- Microsoft's scenario mapping: the IdM Identity Store becomes the Entra tenant (MX_PERSON becomes User, business roles become access packages, privileges become app roles or groups). HR inbound comes from SuccessFactors (with write-back). Provisioning runs through connectors to SAP ECC (BAPIs), SAP Cloud Identity Services and SuccessFactors, plus SCIM/LDAP/SQL/ECMA connectors. SSPR, access reviews, PIM for groups and SoD checks live in entitlement management. Microsoft recommends a staged migration with a parallel staging tenant — [Microsoft Learn](https://learn.microsoft.com/en-us/entra/id-governance/scenarios/migrate-from-sap-idm)
- Microsoft published "Modernize SAP Identity Management with Microsoft Entra" (page last modified 24 Jul 2026) on automated provisioning and governance for SAP and non-SAP apps. Only the page metadata could be read — [Microsoft Entra blog](https://techcommunity.microsoft.com/t5/microsoft-entra-blog/modernize-sap-identity-management-with-microsoft-entra/ba-p/4528596)
- IdM's AS Java base is a security concern after 2030. Running IdM 8.0 on BTP (third-party port) is not supported by SAP — [consiness](https://www.consiness.de/2024/02/21/das-ende-einer-aera-teil-2-4-sap-loesungen/?lang=en)
- Critics say Entra lacks IdM's depth of SAP-specific integration, so third-party IGA vendors are positioning themselves (Pathlock, Saviynt, SailPoint, Omada and others) — [Pathlock](https://pathlock.com/blog/sap-idm-end-of-life/) (vendor source)

**SSO and principal propagation**
- **Principal propagation BTP to S/4HANA:** the user identity from BTP passes through SAP Cloud Connector to S/4HANA. The Cloud Connector backend mapping uses X.509 certificate as principal type, and the BTP destination is switched from BasicAuthentication to PrincipalPropagation. Trust needs system, CA and user certificates (self-signed only for a PoC). Users are matched on a shared attribute, for example the email in SU01 — [SAP Learning: Cloud Connector for principal propagation](https://learning.sap.com/learning-journeys/Setting-Up-SAP-Build-Work-Zone-standard-edition-and-SAP-Mobile-Start-with-SAP-S-4HANA/setting-up-cloud-connector-for-principal-propagation)
- In RISE Private Cloud Edition, SSO integration with Microsoft Active Directory is supported. SAP GUI SSO requires Secure Login Client — [RISE with SAP S/4HANA Cloud PE Service Description Guide v9 2023](https://assets.cdn.sap.com/agreements/product-use-and-support-terms/service-description-guides/rise-with-sap-s4hana-cloud-private-edition-service-description-guide-english-v9-2023.pdf)

### Inferences
- From training knowledge: technically the Cloud Connector issues a short-lived X.509 user certificate for each request, and S/4HANA maps it to a user through transaction CERTRULE (rule-based mapping) and ICM/SSL trust settings. This should be confirmed in SAP Help (Cloud Connector, "Configure Principal Propagation").
- IAS is usually set up as a proxy IdP. The corporate IdP (often Entra ID) stays the leading authentication source, and IAS handles conditional authentication and the trust relationships to BTP subaccounts, S/4HANA Cloud, SuccessFactors and Build Work Zone. BTP's own authorization layer (XSUAA) is gradually being replaced or complemented by IAS-based tokens and AMS for new CAP apps.
- For S/4HANA on-premise or Cloud ERP Private, the typical replacement architecture after IdM is: HR (SuccessFactors or another HR system) feeds Entra ID; Entra ID feeds IPS/Identity Directory; IPS feeds S/4HANA (ABAP users, PFCG role assignment through business role mapping). SoD checks come from Access Control/GRC for SAP HANA or IAG.
- SAP has kept the original name "SAP Cloud Identity Access Governance" in official sources. Some SAP slides abbreviate it to "SAP Identity Access Governance".

### Gaps
- No official SAP Help or Discovery Center page was fetched for current IAS/IPS/AMS pricing or for RISE inclusion as of 2026. Inclusion is cited only from a 2024 partner blog and a non-authoritative advisory site.
- No confirmed 2026 status (preview vs GA) for the Entra–SAP IAG and Entra–SAP Access Control integrations. The latest readable source dates from Oct 2025.
- No source found on whether SAP announced any change to IAG (e.g. folding into GRC for SAP HANA or a sunset) in 2026.

## 2. GRC: SAP Access Control, SAP Process Control, SAP Risk Management, SAP Business Integrity Screening, SAP Audit Management; GRC cloud options

### Takeaway
SAP GRC 12.0 (Access Control, Process Control, Risk Management) reaches end of mainstream maintenance on 31 Dec 2027. The successor is "SAP GRC for SAP HANA" (also called "SAP GRC for SAP S/4HANA"), which runs on S/4HANA 2025 / S/4HANA Foundation 2025 (on-premise or Private Cloud), is Fiori-based and supports hub or embedded deployment. It was in restricted shipment in spring 2026, with GA expected Q3 2026. The cloud option for access governance is SAP Cloud Identity Access Governance.

### Cited Findings
- **SAP GRC 12.0 — END OF MAINSTREAM MAINTENANCE 31 Dec 2027** ("according to the current status"). The end of maintenance does not mean all support stops immediately — [IBsolution](https://www.ibsolution.com/academy/blog_en/cyber-security/sap-identity-and-access-management/maintenance-for-sap-access-control-expires-in-2027-what-comes-next); also [ERP Today, Apr 2026](https://erp.today/sap-grc-hana-update-real-time-processing-2027-transition/)
- **SAP GRC for SAP HANA / SAP GRC for SAP S/4HANA (successor):**
  - Unified platform with modules Access Control, Process Control and Risk Management. The GRC 2026 plan targets HANA databases only, on S/4HANA 2025 or S/4HANA Foundation 2025, on-premise and private cloud. Existing GRC-on-S/4 customers (on-premise or PCE) upgrade under their existing contracts with no new SKU. GRC v12 on any database needs a conversion to S/4 (on-premise or PCE). Planned Access Control integrations: Microsoft Entra ID and SAP Cloud Identity Services Identity Directory as identity sources — [SAP GRC update deck, Aug 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250821_sap_security_governance_risk_and_compliance_update.pdf)
  - Fiori role-based UX for access requests, control monitoring and risk analysis. Real-time analysis on live data instead of batch. Closer alignment with S/4HANA transactional data. AI-assisted features. In restricted shipment via Early Adoption Care in April 2026, GA expected Q3 2026. Customers choose between hub and embedded deployment — [ERP Today / SAPinsider, 10 Apr 2026](https://erp.today/sap-grc-hana-update-real-time-processing-2027-transition/)
  - An earlier partner statement (Jan 2024) named "SAP Access Control Edition for HANA", expected from H1 2026 on-premise and private cloud, independent of S/4HANA. It also mentioned an embedded "SAP Access Control for S/4HANA" variant — [IBsolution](https://www.ibsolution.com/academy/blog_en/cyber-security/sap-identity-and-access-management/maintenance-for-sap-access-control-expires-in-2027-what-comes-next). **Conflict:** the Aug 2025 SAP deck states S/4HANA 2025 / S/4HANA Foundation 2025 as the technical base, so the "independent of S/4HANA" wording from 2024 appears outdated (S/4HANA Foundation = the non-ERP S/4 stack).
- **SAP Access Control:** on-premise GRC tool, licensed per named user (Administrator, Auditor, Superuser), according to an advisory site — [saplicensingexperts.com](https://saplicensingexperts.com/blog/sap-identity-access-management-licensing)
- **SAP Business Integrity Screening (BIS):** fraud management and third-party/sanctioned-party screening. Roadmap: Fiori apps for detection runs and better performance in the Manage Alerts app — [SAP GRC deck, Aug 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250821_sap_security_governance_risk_and_compliance_update.pdf)
- **SAP Audit Management:** audit planning, execution and reporting. Roadmap: audit coverage overview page, sharing recommendations by finding, SAP Workflow integration, enhanced surveys, AI-supported audit report summaries, and import of master data from PC/RM without an RFC setup — [SAP GRC deck, Aug 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250821_sap_security_governance_risk_and_compliance_update.pdf)
- **GRC cloud option:** SAP Cloud Identity Access Governance (see section 1), plus the Entra entitlement management to IAG integration (preview) — [Microsoft Learn](https://learn.microsoft.com/en-us/entra/id-governance/scenarios/migrate-from-sap-idm)

### Inferences
- From training knowledge: SAP Audit Management and SAP Business Integrity Screening run on S/4HANA (BIS was formerly "SAP Fraud Management"). Both have been part of the S/4HANA-based GRC portfolio rather than GRC 12.0 on NetWeaver.
- Process Control and Risk Management follow the same 2027 deadline and HANA/S4 successor as Access Control. The SAP deck groups them in the same platform, but no separate PC/RM maintenance dates were found.
- For RISE customers, GRC for SAP HANA would normally run as a separate system (hub) in the RISE landscape or embedded in Cloud ERP Private. This should be checked against contractual RISE scope.

### Gaps
- No official SAP PAM (Product Availability Matrix) or SAP Note was fetched confirming the exact GA date of GRC for SAP HANA (Q3 2026 is an expectation reported in April 2026) or its end-of-maintenance date.
- No source on whether GRC 12.0 gets extended maintenance beyond 2027 (for example to 2030, like other Business Suite components).
- No data found on "GRC cloud" options beyond IAG (for example SAP Process Control in the cloud or SAP Cloud ERP built-in controls).

## 3. Security operations: SAP Enterprise Threat Detection (incl. cloud edition), SAP Data Custodian, SAP Focused Run, SAP Cloud Security Posture, Code Vulnerability Analyzer, UI Data Protection

### Takeaway
SAP Enterprise Threat Detection is available on-premise and as a BTP-based cloud edition, a fully SAP-managed service with 24/7 SAP security monitoring. In RISE it is an optional, separately priced service. RISE's included security baseline (ECS) covers infrastructure-level SOC, LogServ, EDR and patching, but not application-level threat detection. SAP Focused Run 5.0 is current, with mainstream maintenance beyond 2030. No reliable 2026 status could be confirmed for SAP Data Custodian or for a product named "SAP Cloud Security Posture".

### Cited Findings
**SAP Enterprise Threat Detection (ETD)**
- SIEM for SAP: collects and correlates large log volumes, with an exclusive kernel API that sends logs directly to make manipulation harder. Includes SAP-specific attack detection patterns (no-code creation), risk-based prioritized alerts with publishing to external processes, forensic investigation, threat hunting, anomaly detection, and pseudonymized users that can be resolved with special authorization. Covers the application server and database levels. Deployable on-premise or in the cloud, and offered as a 24x7 managed service. Featured resource: SAP–Splunk integration — [sap.com ETD](https://www.sap.com/products/financial-management/enterprise-threat-detection.html)
- **Cloud edition:** runs on SAP BTP and is a "100% managed service by SAP" (software plus 24/7 SAP security experts). Standard tier: monitoring, prioritized alerts and a monthly report. Extended tier: rapid response, forensic analysis over a set number of months, stronger SLAs and more control over detection rules. Positioned for customers without their own SOC — [SAP News](https://news.sap.com/?p=186741)
- **RISE:** ETD is an optional separate Private Cloud Edition service, priced in blocks of 100 — [RISE PCE Service Description Guide v9 2023](https://assets.cdn.sap.com/agreements/product-use-and-support-terms/service-description-guides/rise-with-sap-s4hana-cloud-private-edition-service-description-guide-english-v9-2023.pdf). SAP's GRC deck lists ETD (including Cloud Edition as a managed service) in the Security and Data Protection pillar. UI Logging can feed ETD for alerting — [SAP GRC deck, Aug 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250821_sap_security_governance_risk_and_compliance_update.pdf)
- **RISE included security (ECS):** organized on the NIST CSF. The slides state "Mandatory Security Features; No hidden security costs". Includes security patch management, LogServ (log storage, 1 month to 10 years retention), EDR, vulnerability scanning and advisory, penetration testing, hacking simulations, 24x7 security monitoring and incident response, SOAR, privileged identity and access management, and immutable backups. Some items exclude the application layer, and application security updates cost extra. "RAVEN" is an ECS service for SAP application security threats, with reports to the customer SIEM. Roadmap items: micro-segmentation/FWaaS (premium NGFW/IPS), HANA default encryption and certificate management (2025/26), BYOK for hyperscalers (2025). The slide grouping is partly ambiguous — [ASUG/SAP RISE Security Framework, Sep 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250918_rise_security_framework_overview.pdf)
- Infrastructure logs in a customer SIEM require the optional LogServ service — [SC World](https://www.scworld.com/perspective/sap-rise-security-where-saps-responsibility-ends-and-yours-begins)

**SAP Data Custodian**
- Key Management Service delivered as SaaS: key provisioning, control and monitoring. Supports BYOK, Hold Your Own Key, customer-controlled keys and CSEK. FIPS 140-2 "for select cases", segregation of duties, multiple key hierarchy levels and audit logs. Works with S/4HANA single-tenant (incl. BYOL), SAP Analytics Cloud Private Edition and S/4HANA on AWS/Azure/GCP. S/4HANA Cloud Private Edition was "in roadmap" (blog undated, approx. 2022/23) — [SAP Community blog](https://answers.sap.com/t5/technology-blogs-by-sap/enhanced-data-security-and-protections-for-sap-cloud-services/ba-p/13549250)
- History: originally launched with Google Cloud and Azure (announced at Microsoft Ignite) for data residency and access transparency on public cloud — [Google blog](https://blog.google/topics/google-cloud/sap-google-data-custodian-partnership); [Azure blog](https://azure.microsoft.com/blog/sap-at-microsoft-ignite-announcing-sap-data-custodian-for-azure/). Thales offers customer-controlled key management for SAP via CipherTrust (CCKM) with SAP Data Custodian APIs — [Thales docs](https://thalesdocs.com/ctp/cm/2.10/admin/cckm_ag/sap/); [Thales press release](https://www.businesswire.com/news/home/20220719005142/en)

**SAP Focused Run**
- Current release SAP Focused Run 5.0 (SP00 shipped Q4 2024). Latest planned feature package FP03 in Q2 2026. Three-year release cycle with two deliveries per year and a one-year overlap between releases. "SAP Cloud ALM and SAP Focused Run are not dependent on the SAP Business Suite, allowing mainstream maintenance beyond 2030." **Not end-of-maintenance** — [SAP Support: Focused Run release strategy](https://support.sap.com/en/alm/sap-focused-run/expert-portal/release-strategy.html)

**SAP Code Vulnerability Analyzer (CVA)** — static code-vulnerability scanning for ABAP, listed in SAP's Security and Data Protection pillar with no roadmap dates — [SAP GRC deck, Aug 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250821_sap_security_governance_risk_and_compliance_update.pdf)

**UI Data Protection (Masking and Logging)**
- Masking roadmap: masking and blocking for OData V4 apps, automatic masking activation across all themes, WebDynpro blocking, multilingual support, and a fallback for missing context attributes. Logging roadmap: alerting, pseudonymization of user IDs, Fiori log analyzer, suspect user list, and migration from classic to streamlined logging customizing. UI Logging integrates with ETD — [SAP GRC deck, Aug 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250821_sap_security_governance_risk_and_compliance_update.pdf)

### Inferences
- From training knowledge: CVA is part of the ABAP Test Cockpit (ATC) security checks and needs a separate licence on-premise. In SAP BTP ABAP Environment and S/4HANA Cloud developer extensibility, security checks are partly included.
- From training knowledge: the official product names are "SAP Enterprise Threat Detection, cloud edition" and "UI data protection masking for SAP S/4HANA" / "UI data protection logging for SAP S/4HANA". Both UI Data Protection products are ABAP add-ons with separate licences and are relevant for GDPR or BDSG employee-data scenarios (masking IBANs and salaries, read-access logging).
- "SAP Cloud Security Posture" could not be confirmed as an SAP product name. Searches returned only third-party BTP posture tools (Onapsis Assess for BTP) and BTP's built-in "security recommendations". It may be a non-SAP term or a very recent announcement.
- Data Custodian: the RISE Security Framework (Sep 2025) lists BYOK for hyperscalers as an ECS roadmap item and does not mention Data Custodian. This may suggest that customer-managed keys in RISE are moving to ECS/hyperscaler KMS rather than Data Custodian. Unconfirmed.

### Gaps
- No official 2026 status for SAP Data Custodian was found (still sold, reduced scope, or retired). This needs checking on the SAP Help Portal or Discovery Center.
- No source confirms a product called "SAP Cloud Security Posture".
- No current ETD cloud edition pricing or RISE-bundle details (for example whether new RISE "Premium" tiers include ETD).

## 4. Sovereignty and infrastructure: RISE technical managed services, hyperscalers, SAP data centers, SAP Sovereign Cloud (Delos Cloud, EU AI Cloud), HEC status

### Takeaway
Since September 2025 SAP has bundled its European sovereignty offer as "SAP Sovereign Cloud": more than EUR 20 bn over ten years, with SAP Cloud Infrastructure (SAP-run EU IaaS), SAP Sovereign Cloud On-Site, Delos Cloud (Germany, public sector, on Azure technology) and sovereign options on selected hyperscalers including the AWS European Sovereign Cloud (Brandenburg). The EU AI Cloud (Nov 2025) adds sovereign AI models on BTP. RISE Private Cloud runs on AWS, Azure and GCP (plus SAP data centers), and as of 8 Sep 2026 also on STACKIT, a German provider certified for RISE.

### Cited Findings
**SAP Sovereign Cloud (announced 2 Sep 2025, Walldorf)**
- Investment of "more than EUR 20 billion" over ten years, covering development, delivery, operations, infrastructure, R&D, operating personnel and compliance. Targets the public sector, defense and regulated industries — [The Register](https://www.theregister.com/2025/09/04/sap_sovereign_cloud/); [SAP press release via Placera](https://www.placera.se/pressmeddelanden/sap-sap-deepens-european-cloud-sovereignty-offering-to-unlock-regional-ai-innovation-20250902)
- Offerings: (1) **SAP Cloud Infrastructure**, IaaS on open-source technology in SAP's own data center network with all data in the EU (Walldorf, St. Leon-Rot and Frankfurt are named as existing sites); (2) **SAP Sovereign Cloud On-Site**, SAP-operated infrastructure in a customer-owned or customer-chosen data center, promising "highest levels of data, operational, technical, and legal sovereignty"; (3) **Delos Cloud**, a German sovereign cloud for the public sector — [The Register](https://www.theregister.com/2025/09/04/sap_sovereign_cloud/); [Constellation Research](https://www.constellationr.com/insights/news/sap-expands-sovereign-cloud-portfolio-europe)
- Scope: SAP Business Suite, SAP BTP and embedded SAP Business AI run in SAP Sovereign Cloud. Already available in multiple EU countries. On-Site is available outside Europe except the US (where SAP National Security Services handles it) — [Constellation Research](https://www.constellationr.com/insights/news/sap-expands-sovereign-cloud-portfolio-europe); [CIO Dive](https://www.ciodive.com/news/sap-data-sovereignty-private-cloud-generative-ai/759046/)
- Analyst caveat: Holger Mueller (Constellation) noted weak sovereign interest from cloud partners and uncertainty about SAP's capex commitment — [Constellation Research](https://www.constellationr.com/insights/news/sap-expands-sovereign-cloud-portfolio-europe)
- **AWS:** AWS and SAP plan to bring SAP Sovereign Cloud capabilities to the AWS European Sovereign Cloud (first region in Brandenburg, Germany, planned by end of 2025; Amazon investment EUR 7.8 bn; independent of other AWS regions). The initial SAP products are SAP BTP and SAP Cloud ERP. Existing SAP Sovereign Cloud on AWS: Australia/NZ (2023), UK (2024), Canada and India (2025) — [Intelligent CIO, 24 Sep 2025](https://www.intelligentcio.com/eu/2025/09/24/aws-and-sap-expand-collaboration-to-advance-digital-sovereignty-across-europe/)
- **OpenAI for Germany:** SAP and OpenAI, for the German public sector, launch expected 2026, running on SAP's Delos Cloud (Microsoft Azure technology). ## 5. Operations: SAP Landscape Management, SAP Cloud ALM operations, SAP for Me, SAP Business Network trust, backup/DR in RISE, shared responsibility (RACI)

### Takeaway

## 6. Data privacy and compliance (DE/EU): SAP Information Lifecycle Management, SAP Data Retention Manager, SAP Personal Data Manager, Data Privacy Integration, GDPR tooling

### Takeaway
For S/4HANA, GDPR deletion and retention rest on SAP Information Lifecycle Management (retention management, simplified blocking and deletion, retention warehouse), which is available in S/4HANA, S/4HANA Cloud and NetWeaver systems. On BTP, SAP Data Privacy Integration (with the Data Retention Manager and Personal Data Manager functions) orchestrates purpose management, deletion and data-subject information across applications.

### Cited Findings
- **SAP ILM:** retention management (rule-based archiving and destruction of transactional data), simplified blocking and deletion (evaluates the lifecycle of personal master data and destroys it when the purpose ends), and retention warehouse (low-cost decommissioning of legacy systems). Available in S/4HANA, S/4HANA Cloud and other NetWeaver systems. Release recommendation: SAP Note 2590321. SAP DMLT offers GDPR analysis and best-practice packages — [SAP user group webinar, Dec 2023](https://assets.dm.ux.sap.com/webinars/sap-user-groups-k4u/pdfs/231214_data_pivacy_and_protection_with_sap_information_lifecycle_management.pdf)
- **SAP Data Privacy Integration (BTP):** associates application data with business purposes (Business Context Manager: legal grounds, data controllers, processes). Deletes data subjects' data at the end of purpose according to residence and retention rules. Retrieves and exports personal data across subscribed applications (transparency, correction). Works with S/4HANA Cloud Public Edition and BTP but does not require them. Licensed via BTP Pay-As-You-Go or BTPEA, in one-tenant blocks with 3–12 month terms — [sap.com Data Privacy Integration](https://www.sap.com/products/technology-platform/data-privacy-integration.html)
- **SAP Data Retention Manager:** SAP product page titled "Orchestrate the lifecycle of business data and manage end user data deletion" — [sap.com Data Retention Manager](https://www.sap.com/mena-ar/products/technology-platform/data-retention-manager.html) (the page title was the only content retrieved)
- CAP-based BTP apps can plug into the data privacy services (Personal Data Manager, Data Retention Manager) — [SAP Community: CAP data privacy services](https://blogs.sap.com/2023/03/18/sapcap-win-customer-trust-using-data-privacy-and-protection-services-on-btp-part-1/)
- UI Data Protection Masking and Logging (see section 3) provides field-level masking and read-access logging — [SAP GRC deck, Aug 2025](https://assets.dm.ux.sap.com/sap-user-groups/pdfs/250821_sap_security_governance_risk_and_compliance_update.pdf)
- The EU AI Act adds compliance requirements on top of GDPR from 2026 — [CIO Dive](https://www.ciodive.com/news/sap-data-sovereignty-private-cloud-generative-ai/759046/)

### Inferences
- From training knowledge: SAP ILM needs a separate licence on S/4HANA on-premise and PCE. An ILM-aware store is required for the ILM retention warehouse. ILM Store on HANA or a certified WebDAV store, for example easy software's EASY for SAP ILM ([easy-software](https://easy-software.com/en/easy-archive/archiving-sap/easy-webdav-for-sap-ilm)), is common. In S/4HANA, "simplified blocking and deletion" through the end-of-purpose check (EoP) for business partner, customer and vendor is standard and essential for GDPR Art. 17 / §35 BDSG.
- From training knowledge: SAP Personal Data Manager is a BTP service for data-subject information requests (GDPR Art. 15). SAP Data Retention Manager is a BTP service that applies residence and retention rules for BTP applications. Both are now offered together under SAP Data Privacy Integration. This should be verified.
- For German test management: test data in S/4HANA test systems falls under GDPR. Anonymization or scrambling tools (SAP Test Data Migration Server is legacy; third-party tools such as EPI-USE DSM or Libelle are common) and UI masking are relevant, but no sources were gathered for them here.
